# 6단계: 구현

slice를 하나씩 만들고 증명한다. 먼저 끝나야 하는 slice가 모두 끝난 slice부터 한다.

## slice 하나를 만드는 차례

1. spec에서 이 slice가 채우는 동작과 증명 방법을 읽는다. slice 상태를 "진행"으로 바꾼다.
2. 실패하는 test를 먼저 쓴다. spec에 적힌 seam에서 동작 하나를 확인하는 test다. 의도한 이유로 실패하는지 돌려 본다.
3. 그 test를 통과시킬 만큼만 구현한다. 다음 test를 내다보고 미리 만들지 않는다. interface는 spec이 정한 대로 처음부터 만든다. 그래서 쓰자마자 통과하는 test가 생기면 구현의 그 부분을 잠시 빼서 test가 실패하는지 확인하고 되돌린다.
4. test 하나, 구현 하나를 되풀이한다. test를 한꺼번에 다 쓰고 구현을 한꺼번에 하지 않는다. 앞 cycle에서 배운 것이 다음 test를 바꾼다.
5. slice의 증명 방법을 실제로 돌린다. 돌린 명령과 본 결과를 spec의 동작 표와 slice 표에 적는다. slice 상태를 "끝"으로 바꾼다.
6. 다음 slice로 가기 전에 지금 상태를 남긴다. commit은 사용자의 지시와 repo의 규칙이 허락할 때 한다. slice 하나가 commit 하나다.

## 좋은 test

- 공개 interface를 통해 동작을 확인한다. 안쪽 구조가 바뀌어도 동작이 같으면 깨지지 않는다.
- 기대값은 코드와 다른 출처에서 온다. 손으로 계산한 값, spec의 예, 알려진 정답이다. 코드와 같은 방식으로 다시 계산한 기대값은 틀릴 수가 없어서 아무것도 확인하지 못한다.
- 안쪽 부품을 mock으로 바꾸지 않는다. 저장소를 직접 들여다보지 않고 interface로 되읽는다.
- test를 세우는 데 큰 준비나 깨지기 쉬운 mock이 필요하면 가장 가까운 실행 확인(명령, script)으로 대신하고 그렇게 했다고 적는다.

## 증명

- 진짜를 직접 확인한다. 기능을 돌리고, 실제 값을 읽고, diff를 본다. 파일 수정 시각, 자기 보고, 지난 출력, "compile된다"는 증명이 아니다.
- 확인이 실패하면 system을 의심하기 전에 확인하는 방법부터 의심한다.
- 되풀이할 확인은 script로 만들어 spec 옆에 둔다. 한 번 쓰고 버릴 것은 repo 밖 임시 폴더에 둔다.

## spec과 어긋날 때

구현하다가 spec에 없는 결정이 필요해지거나 spec대로는 안 되는 것을 찾으면 코드를 먼저 고치지 않는다.

1. 결정을 SKILL.md의 세 종류로 나눈다.
2. 사용자 결정이면 멈추고 SKILL.md의 질문 형식으로 묻는다. agent 결정이면 정하고 spec의 결정 표에 적는다. 실험 결정이면 돌려 보고 적는다.
3. spec을 먼저 고친 뒤 코드를 고친다.

표기만 다르고 뜻이 같으면(언어 version에 맞춘 type 표기 등) spec을 고치지 않는다.

같은 임시방편이 두 번 되풀이되면 shape가 틀린 것이다. 덧대지 않고 2단계로 돌아가 다시 설계한다.

## 다듬기

slice를 끝내기 전에 diff에서 덜어 낸다.

- 코드를 그대로 읽어 주는 주석
- spec이 요구하지 않은 검사, 옵션, 추상화
- 쓰이지 않게 된 호환 코드
- 이 slice와 상관없는 수정

## 여러 slice를 함께

subagent를 쓸 수 있고 지금 할 수 있는 slice가 여럿이며 서로 다른 파일을 고치면 slice마다 새 subagent에게 맡길 수 있다. 지시문에는 spec 경로와 slice 번호를 준다. spec의 내용을 옮겨 적지 않는다. 같은 파일을 고치는 slice는 차례로 한다. subagent의 보고는 증명이 아니다. 증명 방법을 직접 다시 돌린다.

통과: 모든 slice가 "끝"이다. spec의 동작마다 증명이 적혀 있다.
