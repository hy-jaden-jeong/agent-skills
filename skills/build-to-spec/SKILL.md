# build to spec

확정된 spec대로 만들고 증명한다. 무엇을 만들지는 `grill-me` skill이 spec으로 확정한다. 이 skill은 그 spec을 받아 slice로 나누고, 만들고, 검증한다.

끝났을 때 세 가지가 참이어야 한다. spec의 동작마다 실제로 돌려 본 증명이 적혀 있다. 이미 돌아가던 것은 바꾸기 전과 같게 나온다는 증명이 있다. 세 방향 검증의 발견이 보고되었고, 고칠 것은 고쳤다.

- `references/`는 이 SKILL.md 옆 폴더다. `<skills 폴더>`는 이 SKILL.md가 든 폴더의 위 폴더다(예: `~/.claude/skills`, `~/.agents/skills`).
- `grill-me` skill을 같은 skills 폴더에 나란히 설치한다. 사용자에게 처음 묻기 전에 `<skills 폴더>/grill-me/SKILL.md`를 읽고, 그 파일의 "사실과 결정", "round", "질문 형식", "가르치는 법", "묻는 동안"을 모든 단계에서 따른다. 묻는 법이 두 곳에 있으면 어긋난다.

## 들어올 때 확인

먼저 spec을 찾아 읽고 상태를 한두 줄로 보고한다. spec은 사용자가 준 경로에서, 없으면 repo의 관례 위치(`specs/`, `docs/` 등)와 같은 대화에서 찾는다. 못 찾으면 경로를 묻는다. spec 첫 줄의 상태(초안이면 어느 자리인지)가 어디서 이어 갈지 말한다.

| 들어올 때 상태 | 하는 것 |
| --- | --- |
| spec 상태가 "확정" | slice 나누기부터 |
| spec 상태가 "구현 중"이고 남은 slice가 있다 | 남은 slice부터. 상태는 spec의 slice 표가 말한다 |
| spec이 초안이다(열린 결정이 있다) | 같은 대화에서 `<skills 폴더>/grill-me/SKILL.md`를 읽고 남은 단계를 이어 확정받은 뒤 돌아온다 |
| spec은 없고 같은 대화에 확정된 결정 목록이 있다 | `grill-me`의 확정 단계로 spec에 옮겨 확정받는다 |
| 다른 형식 문서(issue, 계획 글)가 있다 | 동작 목록, 열린 결정 없음, 사용자 확정이 모두 있으면 spec으로 받는다. 없으면 `grill-me`가 그 문서를 받아 인터뷰한다. 무엇을 어떻게 할지 적혀 있으면 계획으로, 목표만 있으면 아이디어로 받는다 |
| 아무것도 없다 | 한 module 안에서 끝나고 되돌리기 쉬우면 skill 없이 바로 한다. 아니면 `grill-me` 처음부터 |

- spec 없이 만들기 시작하지 않는다. 무엇을 만들지 정하는 일이 이 skill 안에 다시 생기면 같은 일의 방법이 둘이 된다.
- `grill-me`로 넘길 때 사용자에게 다시 부르라고 하지 않는다. 한 줄로 알리고 같은 대화에서 잇는다.

## 단계

| 단계 | 읽을 파일 | 통과 조건 |
| --- | --- | --- |
| slice 나누기 | `references/slices.md` | 사용자가 나눈 slice에 동의했다 |
| 구현 | `references/build.md` | slice마다 증명이 spec에 적혀 있다 |
| 검증 | `references/verify.md` | 발견한 것을 보고했고, 고칠 것을 정해 고쳤다 |

- 이미 돌아가는 것을 바꾸는 일이면(spec에 "기존 … 그대로" 동작이 있으면) slice 나누기 때 `references/golden-master.md`도 읽는다. 기준 대상과 굽는 명령을 slice와 함께 동의받고, 첫 slice의 코드를 고치기 전에 기준을 굽는다.
- 단계에 들어갈 때 그 단계의 파일을 읽는다. 다음 단계의 파일은 통과 조건을 채운 뒤에 읽는다. 뒤 단계가 먼저 보이면 앞 단계를 서둘러 끝내게 된다.
- 통과 조건은 사용자의 말이나 spec에 적힌 내용으로 확인한다. 짐작으로 넘어가지 않는다.
- 뒤 단계에서 spec이 틀렸다는 것이 드러나면 spec을 먼저 고친다. 무엇을 만들지가 바뀌는 수정이면 `grill-me`의 그 단계로 돌아가 확정받고 다시 내려온다.

## spec이 진행 상태다

spec 한 파일이 진행 상태다. 진행 상태를 spec 밖에 따로 적지 않는다.

- 이 skill이 spec에 더하는 절(slice 표, 회귀 기준, 검증 기록)과 동작 표의 증명 칸은 `references/spec-sections.md`를 따른다. 나머지 절의 형식은 `<skills 폴더>/grill-me/references/spec-format.md`에 있다.
- 대화가 끊겼다가 이어지면 spec을 읽고 상태를 보고하고 남은 slice부터 한다.
- 대화가 길어졌으면 spec을 고쳐 둔 뒤 새 대화에서 spec을 읽고 이어 가자고 제안한다.

## 사용자가 확인을 맡겼을 때

사용자가 "묻지 말고 끝까지 하라", "직접 확인하고 문제없으면 가라"처럼 확인을 맡기면 그 뒤의 사용자 확인(slice 동의, spec 동작이 요구한 결과물 승인, 고칠 발견 고르기)을 agent의 이중 확인으로 바꾼다. spec이 아직 확정 전이면 `grill-me`의 "나머지는 알아서 해" 규칙(질문 형식 절)대로 추천으로 정해 확정한다. 결과물을 직접 열어 보고 사실을 근거와 대조한다. spec에 "사용자가 맡김(날짜)"과 agent가 확인한 것을 적는다. 되돌리기 어렵거나 밖으로 나가는 행동(push, 전송, 삭제)은 사용자가 그 행동까지 맡겼을 때만 한다.
